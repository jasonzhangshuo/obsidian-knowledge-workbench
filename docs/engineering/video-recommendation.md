# 每日视频推荐第一版

推荐逻辑归属本仓库，入口 `skills/daily-video-recommendation/SKILL.md`，确定性工具 `tools/video_recommendation.py`。现有 Codex dot 每日任务执行语义提取、公开搜索、字幕评审并在原对话输出；没有另开模型服务。旧桌面 heartbeat 保持暂停，本次不改变现有每日推送或新增调度。调度归属登记在 LifeOS `docs/engineering/schedule-ownership.md`，实际启停状态以对应任务管理器为准。

## 已实现

- 用户已确认、仍开放的 `memory_todo` 问题优先，先选具体待讨论子问题，再用近期材料确定切口。创建/维护日期不冒充用户确认日期；长期开放问题不受近期证据90天截止影响，也不刷新日期增权。读取失败、无开放记录、无可确认的问题分别说明；无可用问题时回退到近期证据。

- 微信读书两自然周阅读量、最近30天个人划线与想法，最多5本。显式报告截断/未读分页；缺凭证、升级通知、错误不当成空数据。
- Wiki 原生 MCP 与浏览器限定历史由 skill 调用，原始证据日期、推断及缺失状态分开。访问不能当播放时长；精确播放时长采集尚未实现。
- 证据按14天半衰期，同主题同原始材料只保留最强信号，最多3个独立材料；机器生成、已归档、自动访问不能计入兴趣。
- 候选由字幕评审后按相关性/新信息/具体内容/观看成本排序，热度不进入质量分。陌生频道指可用记录未出现，非全账号证明。
- YouTube 官方 search/videos/commentThreads 适配器（环境变量 YOUTUBE_API_KEY）；无 key 时 skill 使用公开搜索及浏览器元数据。评论关闭/不可用不等于零评论。
- 既有字幕 CLI 复用。第一版推荐门槛检查视频ID、已知时长、字幕首尾覆盖、全部cue审阅范围。它能拒绝明显截断，不能数学证明字幕没有缺句，仍需语义检查。
- SQLite 每日唯一领取及跨天视频去重，准备状态不冒充送达。失败次日再试，不自动删除锁/补发。

## 本机安装与操作

源码以本仓库 `main` 为维护入口，功能 worktree 仅用于开发，不作为长期运行依赖。将 SKILL.md 复制到 `~/.codex/skills/daily-video-recommendation/`，同目录放不入库的 runtime.json，字段为 `cli_path`（主仓库 `tools/video_recommendation.py` 的稳定绝对路径）、`transcript_cli`（既有字幕工具绝对路径）、`state_dir`（私人运行目录）。不得将配置或证据复制到 Git。安装后新会话可发现；现有每日任务读取安装后的绝对 Skill 路径。更新源码后同步复制 Skill，保留 runtime.json 的其他字段。

```bash
python3 tools/video_recommendation.py --help
python3 -m unittest discover -s tests -p test_video_recommendation.py -v
```

状态路径是所有手动/定时运行共同的数据库。`begin` 先领取；源数据和候选卡保存到私人目录；`rank`、`select` 只做评分；`finish` 校验并标 prepared；当前线程随后输出卡片。中断的 running/failed 当天不会自动重跑，防止重复推送。需要停止时，在管理现有 dot 每日任务的界面暂停该任务；已暂停的桌面 heartbeat 不恢复。保留证据与数据库，不启动替代任务。

## 准备、发送与送达的边界

- `running`：当天已领取；`failed`：领取后失败；`prepared`：字幕和卡片校验通过。三种状态都会阻止自动重复领取。
- `finish` 只更新本地准备记录，不发送消息，也不产生“已送达”或“已读”凭证。旧的 `prepared` 记录保持原状，不能补标成功。
- 原对话中的实际消息与消息工具返回值用于单独核对发送情况。工具接受发送不等于设备送达或用户已读；结果不确定时不自动重发。
- 本次隔离验证不证明自然定时触发、系统通知或实际送达可靠性。送达回执、补发机制和调度迁移是独立后续工作，本次没有新增。

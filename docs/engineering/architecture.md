# 维护归属与架构

用户于 2026-11-07 指定本项目为这次开发与后续开发的维护位置。

## 内容与代码

Obsidian 是长期知识正文的正式存储。原书、逐页文字、章节、概念、出处和分析归档保存在 Vault，不以 Codex 对话目录作为唯一副本。Claudian 是日常整理维护入口，Wiki Skill 是规则，知识正文不是 Skill 的副本。

本项目管理支持该工作流的程序、提示模板、测试、接口代码和技术文档。已安装 `obsidian-wiki 2026.11.2` 的源码由上游/uv 管理；本机链接和配置不纳入 Git。后续确需修改上游时记录具体版本和补丁，不把整个安装环境复制进仓库。

## 后续实施顺序

1. 在本项目固化书籍目录、来源标识、页码映射、校验和失败重试；复用已安装 Wiki 的内容规则。
2. 在本项目实现独立的只读知识 MCP；先限定一个书籍目录，支持中文全文检索、知识页读取、原文检索和按书籍/物理页读取。
3. 分别验收 Codex 和 Hermes 的实际工具调用、原文出处，以及资料不足时不编造。
4. 再扩展多书、跨书关联和 Coach Skill。Coach Skill 保存查询/回答逻辑，知识正文仍只有 Vault 中的一份正式内容源。

服务返回来源标识、原文件哈希、课次、物理页、原文和草稿状态；模型在调用方做解释。知识访问不依赖 Claudian 常开。Sparky 的健康事实与分析仍归原项目，本仓库不复制其实现或个人健康数据。

## 数据边界

只读取用户交付的资料及相应书籍空间，排除 `_private/Morning Pages/`。默认检索和校验禁止遍历整个 Vault。知识源文件不可被清理步骤覆盖；引用只忽略排版空白，不删除数字、标点或中间句子。结构化产物保存不等于 `verified`，内容审校状态独立记录。
